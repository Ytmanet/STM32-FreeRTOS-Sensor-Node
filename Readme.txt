阶段 0：验证最小 UI（当前卡点）
烧录现在这个版本，确认两件事：
LCD 上能显示 "Hello LVGL"（哪怕就一行字）
串口不再卡死，mem total=24576 free=... 那行正常打印
完成标准：屏幕有字 + 串口不死循环。这一步过了，后面所有问题都只是"往里加东西"。
阶段 1：清理 + 恢复完整 UI
删掉所有 [LVGL]/[FLUSH] 调试打印
把最小 UI 换成完整版：深色背景 + 顶部标题 + 三行数据（温度 / 湿度 / ADC 电压）
数据来源就是现有的 q_sensor2display 队列，Display 任务里刷 label 即可
完成标准：屏上三行数据跟着 SHT30 和 ADC 实时变化，刷新流畅。
阶段 2：接入触摸
移植正点原子 TOUCH/gt9xxx.c（引脚 PB1=SCL / PF9=SDA / PF10=INT / PF11=RST 已确认不冲突）
需要适配它依赖的 delay/24CXX，或者直接用你项目里现成的软件 I2C 思路重写读寄存器部分
在 lv_port_indev 里把触摸坐标转成 LVGL 事件
完成标准：LVGL 官方自带的 demo widget 能点按响应（加个按钮点击变色之类）。
阶段 3：桌面化
建一个"桌面"页面：一排图标（时钟 / 温湿度 / ADC），每个图标是一个 lv_btn + 图标
点击图标 → 切换页面（lv_obj_move_foreground 或页面栈方式），做一个返回按钮
内存不够就先不用图片，用 lv_symbol 字体符号 + 文字标签
完成标准：桌面 → 点图标进 App → 返回键回桌面，能完整走通。
阶段 4：App 逐个填内容
时钟 App：RTC 或者直接用系统 tick 计时，显示日期时间，可加秒表
温湿度 App：大字显示 SHT30 温度湿度 + 历史曲线（lv_chart，这个展示价值高）
ADC App：电压实时显示
完成标准：每个 App 打开后有真实数据、有独立功能，不是空壳。
阶段 5：打磨（可选，时间紧就跳过）
图标间切换动画、数据刷新只更新变化的 label
内存优化：确认 24KB LV_MEM 峰值占用，必要时降缓冲
完成标准：观感流畅，无明显刷新闪烁。
阶段 6：收尾提交
清理 .o/编译产物，补 README（LVGL 移植要点、内存配置、触摸接线、演示视频/GIF）
git 提交，推到 GitHub 现有仓库或开个新仓库当亮点
最终效果
开机后 LCD 变成一个"类手机系统"的桌面：深色背景下几个图标（时钟、温湿度、ADC 电压），触摸点击进入对应 App——时钟 App 显示日期时间，温湿度 App 显示 SHT30 实时数据，还能画曲线；返回键回桌面。数据来自你现有的传感器 + FreeRTOS 队列 + 串口协议，整个系统是一个完整的"采集 → 传输 → 显示"闭环。
对你简历的讲法就是一句话：基于 STM32F103 + FreeRTOS + LVGL 的多任务传感器桌面系统，触摸交互、多页面、实时数据刷新全都有。
时间建议：阶段 0 到 4 是主体，两周内能拿下（阶段 2 触摸最花时间）；阶段 5 看进度，阶段 6 半天。
